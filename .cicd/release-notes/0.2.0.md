# XmaxSDK Windows 0.2.0

## What's New

- C++17 SDK with a C ABI and an optional header-only C++ owner wrapper.
- SDK-owned Media Foundation camera capture, device switching, source-bound BGRA/NV12/I420 video and optional PCM input.
- Local/remote preview frames, serialized remote audio/video delivery with presentation timestamps, and trajectory interaction.
- Separate connection and generation, cached conditions, dual keepalive and rollback.
- Five-tier adaptive quality with per-model/direction history persisted for one hour.
- SDK storage uploads/downloads, image safety checks, progress and cancellation.
- Qt, WPF and WinUI 3 XLab demos using public SDK interfaces; C# wrappers and optional WPF/WinUI video controls.
- Remote audio/video recording and MP4 saving in Qt and WinUI 3 XLab.
- WinUI recording finalization uses a XAML-only loading indicator to avoid the unpackaged Windows ARM layout crash in the default ProgressRing template.
- Windows MSVC SDK/Demo packages, export audits, checksums and isolated installed consumers.
- XmaxLogger business/performance masks, localized categorized diagnostics, native debugger output and a bounded polling queue, with credential redaction.

## API Changes

- WPF and WinUI 3 rename the public video control from `XmaxVideoView` to `XmaxRealtimeVideoView`. Update XAML element names and C# type references; the old type name is not retained as an alias. Package IDs, namespaces, `VideoSource` and `ContentMode` remain unchanged. This is a managed source/XAML compatibility change and does not change the native C ABI.
- C# SDK, WPF and WinUI packages include XML API documentation; builds and package validation check that the documentation is present and matches the assembly.
- ABI version remains 1; original structure layouts and the remaining exports are retained.
- Three additive logger exports configure/query process-wide logging and poll UTF-8 records; logging remains disabled by default.
- Model capability queries supply supported targets and defaults; see the [native integration guide](../../Materials/usage.md) for format and compatibility rules.
- Removed unsupported frame-interpolation controls and their capability flag; other capability values are unchanged. Native window presentation uses CPU/GDI.
- Source-scoped external media receivers, remote media callbacks and trajectory APIs are available. Resource ownership and threading contracts are defined in the [public header](../../include/xmax/xmax.h).

## Validation

Local release packaging requires Windows MSVC core and Agora builds, all CTest suites, the Qt UI smoke test,
DLL export and import checks, package checksum verification and independent C, C++ and .NET consumers
against the extracted native packages. Managed candidates additionally run C# ABI/integration and WPF/WinUI checks.
Package contents, local dry runs and explicit GitHub uploads are defined in
the [release workflow guide](../README.md). Publishing does not use GitHub Actions.

Camera/device compatibility, audio, real cloud generation, COS service integration and sustained realtime
performance require hardware/service acceptance. Automated tests use controlled inputs and no real API credentials.
