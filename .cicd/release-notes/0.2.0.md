# XmaxSDK Windows 0.2.0

## What's New

- C++17 SDK with a C ABI and an optional header-only C++ owner wrapper.
- SDK-owned Media Foundation camera capture, device switching, external BGRA/NV12/I420 input and local/remote preview frames.
- Separate connection and generation, cached conditions, dual keepalive and rollback.
- Five-tier adaptive quality with per-model/direction history persisted for one hour.
- SDK storage uploads/downloads, image safety checks, progress and cancellation.
- Qt XLab using only the public SDK interface, and a minimal .NET P/Invoke consumer.
- Windows MSVC SDK/Demo packages, export audits, checksums and isolated installed consumers.
- XmaxLogger business/performance masks, localized categorized diagnostics, native debugger output and a bounded polling queue, with credential redaction.

## API Changes

- ABI version remains 1; the initial 50 exports and original structure layouts are retained.
- Three additive logger exports configure/query process-wide logging and poll UTF-8 records; logging remains disabled by default.
- Model input sizes are 1920x1024 or 1024x1920, with 1-60 fps.
- Frame interpolation reports unsupported; current native window presentation uses CPU/GDI.
- GPU texture zero-copy, external audio and trajectory input are outside this release's public API.

## Validation

The release pipeline requires Windows MSVC core and Agora builds, all CTest suites, the Qt UI smoke test,
DLL export and import checks, package checksum verification and independent C, C++ and .NET consumers
against the extracted packages. A successful candidate build is required before publishing.

Camera/device compatibility, audio, real cloud generation, COS service integration and sustained realtime
performance require hardware/service acceptance. Automated tests use controlled inputs and no real API credentials.
